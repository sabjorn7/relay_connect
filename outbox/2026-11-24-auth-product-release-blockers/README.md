Это фактические браузеры и SDK, синтетические HTTP-ответы. Разные страницы имеют по одному экземпляру SDK и общее origin storage. Промежуток старой очистки задаётся поддерживаемым асинхронным storage adapter: тест доказывает возможность порядка операций, не частоту естественного воспроизведения. Для no-locks отключено свойство navigator.locks в современном браузере; это проверка ветки отсутствия API, не тест физического старого Safari. Закрытие страницы не равно убийству процесса браузера, отключению питания или заморозке ОС.

Старый SDK не использует новую блокировку записи. Поэтому блокировка в новом SDK сама по себе не обеспечивает безопасный переход. Также исходный патч требует Web Locks для всех записей, включая явный logout: отсутствие API становится функциональной регрессией выхода.

**Продуктовая интеграция остановлена согласно условию задачи. Итоговый релизный diff и закреплённая production-зависимость не подготовлены: кандидат нельзя объявить готовым.** Ранее проверенные authRecovery, confirmedSession и wwPlugin сохранены без изменений. Исправленный SDK не изменялся в этой задаче.

## Минимальное решение для отдельного согласования

1. Старые вкладки: рассмотреть версионированное имя session storage для нового кандидата, без копирования старых refresh tokens. Потребуется повторный вход. Старый SDK тогда не удалит новую локальную запись. Простое переименование недостаточно считать готовым решением: отдельно проверить действующие adapters/cookies, VK callback, BroadcastChannel и серверные последствия global logout из старой вкладки. Это изменение хранения и поведения сессии требует разрешения; не реализовано. Просьба вручную закрыть старые вкладки не даёт гарантии для всей аудитории.
2. Web Locks: отдельно доработать только явный logout так, чтобы отсутствие механизма записи не оставляло локальные персональные данные после команды выхода. Не заменять общую блокировку process-local fallback для refresh: это вернёт межвкладочную гонку. До согласования безопасного поведения входа/refresh без Web Locks универсальный релиз остаётся заблокированным. Нельзя молча возвращать старый SDK или показывать ложный успешный logout.
3. После согласования этих границ — повторить новые тесты, затем прежнюю матрицу. Продолжать упаковку релиза только после устранения критических FAIL.

## Предложение воспроизводимого закрепления, не применено

Хранить проверенный локально собранный архив SDK в репозитории под относительным `vendor/auth-js-2.119.2-mg.1.tgz` вместе с LICENSE, исходным patch, SHA upstream-исходника и командой сборки. Override `@supabase/auth-js` должен ссылаться на `file:vendor/auth-js-2.119.2-mg.1.tgz`; package-lock фиксирует тот же артефакт и integrity. Никаких postinstall-правок node_modules или абсолютных путей. Локальная сборка и CI выполняют npm ci по одному lockfile. Это план упаковки, не утверждение о пройденной проверке такой установки.

Проверить в двух чистых каталогах: npm ci, npm ls с единственной ожидаемой версией auth-js, SHA установленного CJS/ESM, отсутствие иных изменений lockfile, SDK/browser tests, Vite build. Компилятор SDK и его lockfile также закрепить; не обещать побайтовую воспроизводимость пересборки до сравнения двух архивов. До этого существующий тестовый tarball не является продуктовым способом поставки.

До завершения этих шагов не запускать Deploy App.

При будущем переходе на новый storage key простой возврат старого frontend-коммита не сохранит автоматически новые сессии; план отката должен предусмотреть повторный вход без копирования/воскрешения старых токенов. Зафиксировать рабочий production SHA непосредственно перед согласованным выпуском. Не изменять серверные сессии, RLS или БД в рамках отката frontend.

Отдельные согласования: изменение ключа хранения/повторный вход; поведение неподдерживаемых браузеров и доработка SDK; способ vendoring; Node CI; затем сам релиз. В этом пакете нет установщика или команды публикации.

## Воспроизведение

Скопировать tests/auth-release-boundaries.browser.mjs в tests отдельного кандидата из 03e44e2. Он должен использовать прежний локально собранный patched SDK. Указать OLD_AUTH_MODULE — абсолютный путь к dist/module/index.js отдельной неизменённой версии auth-js 2.70.0; PLAYWRIGHT_MODULE — путь установленного Playwright. Эти пути относятся только к тестовому стенду, не к продуктовым зависимостям.

```sh
node tests/auth-release-boundaries.browser.mjs
```

Ожидаемый результат текущего кандидата: шесть FAIL и два PASS; `releaseReady=false`. Runner завершает сбор всех восьми результатов обычным кодом выхода: gate — поле releaseReady, не exit code. Внешние HTTP-запросы блокируются. Старый SDK берётся только для чтения. Никаких реальных пользователей и платежей.
