# Существующий клубный чат — итоговый локальный кандидат

Продолжение `5b56ab2`. База приложения `123cdab5222d42803adc310f53bdfccfde4cc9a9`.
**Подготовлен для согласования. Production не менялся, Deploy App не запускался.**

## Реализовано

- Существующие история/таблица club_chat/WeWeb composer сохранены, новый чат не создаётся.
- Имена/аватары/инициалы и ссылки на профиль по ID; собственные/чужие сообщения, дата/время браузера.
- ChatMessageText и ChatLinkPreview переиспользованы для ссылок и карточек; исходный текст не заменяется HTML.
- Текст и существующие фото/delete-popup работают через прежние workflows. История ограничена текущим клубом, корректируется прокрутка после async layout.
- Новые файлы и изображения: приватный upload, просмотр через короткую signed URL, inline preview изображения. Без публичного fallback. Файлы идут отдельным сообщением, подпись вместе с вложением не добавлена.
- Голосовые: существующие MediaRecorder format helper, MP3 encoder и VoiceMessagePlayer. Предпросмотр, отмена, отправка, запрет второго старта во время ожидания микрофона/записи/обработки/выбранного вложения; очистка при logout. Chrome успешно записывает/отправляет синтетическое аудио. Safari успешная запись пока не подтверждена — см. TESTS.md.
- Повтор файла после RPC error использует прежний request UUID, не загружает уже сохранённый объект второй раз.
- В существующую web-push-send добавлены два выключенных по умолчанию события: новое club_message и опубликованный club_post. Прежние настройки send_notif, allowlist, VAPID, icon/badge и delivery переиспользуются.
- На экране уведомления только «МитГуру» и «Новое сообщение в клубе» / «Новый пост в клубе». Ссылка содержит ID клуба для перехода, но не текст/имя/название/фото.
- Редактирование сообщения/поста и повторный переход публикации не повторяют enqueue; проверено в локальном SQL-тесте.

## Что исключено из прежнего пакета

Нет новых таблиц `club_chat_feature_flags`/`club_push_dispatch`. Нет изменения RLS существующих club_chat/club_posts/club_subs. Нет изменений членства, подписок, цены, Auth, платежей, общего чата или legacy Expo/n8n.

Кандидат не переносит read/unread/realtime-модель таблиц messages/chats и управление составом обычной группы в клуб. Это не требуется для перечисленных сценариев; полного паритета всех функций групп не заявляем.

## Необходимые отдельные серверные изменения

- `attachments.proposed.sql`: пять полей вложения и unique index в существующей club_chat; приватный bucket; политики только для нового bucket; read-only access helper, capability RPC, idempotent send RPC. Нет изменения существующих RLS/GRANT на клубные таблицы. Capability по умолчанию false.
- `push.proposed.sql`: по одной служебной отметке enqueue в существующих club_chat и club_posts; два выключенных trigger и функция, использующая прежний pg_net/push_send_key/web-push-send. Новых таблиц/сервисов нет.
- `enable-after-approval.sql` и `disable.sql`: исключительно для будущего согласованного включения/отключения. Сейчас не применять.

Детали в SERVER.md. SQL предложен, а не установлен. Доставка push на реальные устройства не выполнялась.

## Артефакты

Единый `changes.diff` содержит frontend и Edge изменения относительно базы, включая ранее проверенный код. `page/page-changes.json` и SHA-проверяемый `page/apply-page.py` содержат два точечных изменения экспортированного JSON: поля вложения и фильтр клуба. Однострочную полную страницу не размножаем в diff, чтобы не публиковать несвязанные данные. Применять вместе на чистую базу, не поверх старого пакета.
