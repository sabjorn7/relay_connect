## Состав установки

Только `web-push-send/index.ts` и новый `web-push-send/club.mjs` внутри обнаруженного functions mount. SHA ожидаемого baseline index: `413227d89fcb42c685678f34c6f08da6637ede1af80912475380e67c5956c7d7`.

Status обнаруживает mount из Docker inspect, выводит SHA исходника, результат сравнения, состояния двух триггеров, булевы признаки наличия секретов и режим allowlist (без значений/ID). Значения ключей не печатаются. Проверяется отсутствие включённого PUSH_CLUB_ENABLED; кастомная передача этого флага в main требует отдельной проверки и останавливает пакет.

Install разрешает замену только при точном baseline SHA, отсутствии неизвестного club.mjs, выключенных триггерах/club gate и исправной существующей конфигурации push. При drift останавливается до изменений. Env, глобальный PUSH_ALLOWLIST, VAPID, PUSH_SEND_KEY и main/index.ts не меняет. Обычные события остаются в прежнем коде. Helper и index записываются с исходными правами/владельцем.

Резервная копия создаётся **при установке** в `/var/lib/mg-deploy/club-push-20261126/` (root-only): исходный index, metadata и fingerprint полной конфигурации для проверки drift; значения env в новый state не копируются. Существующий backup не перезаписывается.

Для загрузки изменённого кода установщик выполняет один restart контейнера `supabase-edge-functions`. Это кратковременно затронет все Edge Functions общего runtime, хотя файлы остальных функций не меняются. Этот конкретный эффект должен быть учтён администратором при одобрении установщика; сейчас restart НЕ выполнялся.

Smoke до замены: анонимный 401; прежние direct_message/stream_start/chat_message с отсутствующими ID возвращают 400 до обращения к получателям. После замены дополнительно два club-события с синтетическими UUID возвращают `disabled=true`, `sent=0`, без вызова доставки. Никакие реальные сообщения/посты/заказы не создаются.

Если проверка установки не проходит — автоматический возврат старого index, удаление только известного нового helper и повторный restart. Отдельный rollback защищён SHA backup/current, проверкой выключенных триггеров и неизменности env; посторонние изменения не перезаписывает. Не удаляет пользовательские данные. После успешного rollback — smoke прежнего обработчика.

## Ограниченный пилот — пока не включать

Подготовленный ранее pilot SQL ограничивает клуб, но не конкретного получателя. Он считает 36 активных участников и останавливается на лимите 1–10. Самовольно повышать лимит до 36 нельзя: это не создаёт контроль получателей.

Для следующего согласования нужно выбрать тестового получателя/устройство и способ исключить остальных. Минимальный вариант: отдельный club-only allowlist в существующем клубном helper, без изменения глобального PUSH_ALLOWLIST и обычных событий. Этого расширения НЕТ в текущем согласованном handler, в этой задаче оно не внедрено. Альтернатива — явное согласование всех фактических получателей клуба после их проверки; это уже не пилот одного устройства.

До выбора и отдельного одобрения адресатов НЕ устанавливать PUSH_CLUB_ENABLED=true и НЕ включать триггеры. Никакие реальные уведомления этим пакетом не отправляются.

После отдельного согласования recipient scope и устройства: включить club gate/два клубных триггера только для UUID `737b8824-88b8-4cee-b50b-3f4ed3b59683`, отправить согласованное сообщение и опубликовать согласованный пост, проверить оба уведомления и переход, проверить отсутствие повторов при edit и opt-out, затем выключить клубные триггеры. Сообщения/посты заранее здесь не создавались.

Немедленное выключение будущего пилота — `disable-club-push.sql`: только два новых триггера. Старые Expo/n8n и обычные чаты не затрагиваются. Уже поставленные pg_net запросы этим SQL не отменяются; для прекращения обработки новых входящих club-событий дополнительно выключается только PUSH_CLUB_ENABLED штатной защищённой конфигурацией. Ни global PUSH_ALLOWLIST, ни PUSH_ENABLED менять не нужно.
