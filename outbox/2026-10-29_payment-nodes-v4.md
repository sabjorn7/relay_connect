# Ноды оплаты v4 — хранение PRODAMUS_SECRET + правки по ревью

## 1. Где и как хранить PRODAMUS_SECRET (по нашему n8n)
**Наш инстанс — n8n 1.90.2** (`2.85.0` в прошлом отчёте — это версия MCP-тула, не n8n). Это ветка **1.x, не «v2»**.

- **`$env` в Code-ноде:** управляется `N8N_BLOCK_ENV_ACCESS_IN_NODE`, **по умолчанию `false` → `$env` доступен**. Блокирует его только если на хосте явно выставлен `=true` **или** включены внешние task-runners (`N8N_RUNNERS_ENABLED=true`) и переменная не проброшена в процесс раннера. Прочитать env самого n8n-процесса через API я не могу → не утверждаю на 100%, нужна 10-секундная проверка (ниже).
- **Settings → Variables (`$vars`):** это **Enterprise-фича** (нужна лицензия). На self-hosted community она недоступна → **не закладываемся** на `$vars`.

**Рекомендация (рабочая, безопасная, без лицензии):** хранить секрет как **переменную окружения самого n8n-процесса**, читать через `$env.PRODAMUS_SECRET`. Значение не в JSON воркфлоу, не в БД, не в логах.

Пошагово (владелец, значение вводит сам, мне не присылать):
1. На хосте n8n добавить в окружение сервиса `PRODAMUS_SECRET=<значение>`:
   - systemd: `Environment=PRODAMUS_SECRET=...` в unit (или `EnvironmentFile`); docker/compose: `environment:` / `.env`; pm2: `env`.
   - Убедиться, что **не** стоит `N8N_BLOCK_ENV_ACCESS_IN_NODE=true`.
2. Перезапустить n8n.
3. **Проверка доступа (10 сек):** временная Code-нода `return [{ json: { present: !!$env.PRODAMUS_SECRET } }]` → Execute Node → ждём `present: true` → удалить ноду. Значение не выводить.
   - В самой VerifySign уже есть поле **`secret_present`** и оно пишется в `detail` AuditWarn — после включения WARN сразу видно по `payment_audit`, если секрет не виден (значит env заблокирован/не задан — тогда фолбэк ниже).

**Фолбэк, если `$env` окажется заблокирован** (или неудобно трогать хост): перенести проверку подписи в БД — секрет в service-role-таблице, RPC `verify_prodamus_sign(serialized, sign)` считает HMAC через `pgcrypto`; тогда секрет **вообще не попадает в n8n** (ни в env, ни в логи executions). VerifySign в этом варианте только сериализует тело и шлёт строку в RPC. Готов прислать отдельный SQL + вариант ноды, если проверка п.3 даст `present: false` — скажи.

## 2. Правки нод по ревью (v4)
1. **`secret_present`** добавлен в вывод VerifySign (`!!SECRET`) и в `detail` AuditWarn (и AuditWarn/AuditDuplicate уже содержат `payment_status`). Сразу видно отсутствие секрета.
2. **`alwaysOutputData` убран с `IF_AlreadyPaid`** — остался только на `CheckPaid` (где он и нужен: при «заказ не найден» отдать item, чтобы сработала false-ветка). Проверка пустых записей: `AuditDuplicate` (true-ветка) срабатывает **только** когда `CheckPaid` нашёл заказ с `paid=true` → в неё всегда приходит реальный item, `order_id`/`paid` берутся из `$('Shop')` → **пустых строк в `payment_audit` не создаётся**. При «не найдено» (`CheckPaid` вернул пустой item) IF по `$json.paid=undefined` уходит в false-ветку — не в AuditDuplicate.
3. **RestoreBody:** `return [{ json: $('Shop').first().json }];` — без метаданных pairedItem.
