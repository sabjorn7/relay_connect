# Реальная PWA-проверка — после отдельного разрешения

Сейчас ни один шаг с уведомлением не выполнять.

1. Владелец указывает тестовые аккаунты UUID и устройства. Сверить, что PWA установлена, уведомления разрешены, используется выбранный аккаунт и send_notif=true. Несколько подписок одного аккаунта означают несколько возможных устройств; аккаунт не равен одному телефону.
2. Зафиксировать согласие на получение уведомлений пилота (в том числе новых реальных событий этого клуба за время теста), согласовать окно. Не менять членство и не создавать новые подписки принудительно.
3. После установки ограничивающего helper и отдельного enable проверить текстовое сообщение от ДРУГОГО авторизованного участника. Отправитель исключается, поэтому отправка себе не проверяет доставку. Тестовый текст без персональных данных.
4. PWA получателя свернуть/закрыть; проверить фактическое уведомление на Android/iOS. Текст — только «Новое сообщение в клубе», без имени, текста и названия клуба. Проверить штатный значок.
5. Нажать push: открывается `/club/?club=737b8824-88b8-4cee-b50b-3f4ed3b59683`; приложение штатно проверяет сессию. Автоматическое переключение на вкладку чата не обещается существующим маршрутом.
6. Уполномоченный автор публикует один согласованный тестовый пост. Получатель, отличный от автора, получает «Новый пост в клубе». Проверить переход.
7. Изменить сообщение/пост: повтор не должен появиться. Не сбрасывать markers напрямую в production и не отправлять callbacks вручную. Локальный PostgreSQL-тест уже проверяет edit/reset/republish.
8. Проверка opt-out — только через обычную настройку согласованного аккаунта с разрешением владельца: send_notif=false должен исключать уведомление. Другие аккаунты не изменять. Если этот тест не согласован — NOT TESTED, а не PASS.
9. Проверить существующий обычный chat push на согласованном аккаунте, если отдельно разрешена реальная отправка такого сообщения. Не использовать чужой чат.
10. Немедленно выполнить scoped disable по окончании окна либо при неверном адресате/содержимом/ошибке. Не удалять реальные сообщения и подписки автоматически. Сохранить только время, безопасный UUID, тип устройства с согласия владельца и результат received/clicked; не публиковать endpoint, токены или скриншоты с персональными уведомлениями.

Доказательство доставки — наблюдение на согласованном устройстве. Provider accepted/HTTP 201 или существующая строка push_subscriptions не равнозначны фактическому показу пользователю.
