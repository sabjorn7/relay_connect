## Минимальное изменение

Только существующий `web-push-send/club.mjs` получает фиксированный серверный `CLUB_PILOT` с одним UUID клуба и списком одобренных user IDs. В текущем пакете список пуст и fail-closed: даже при случайно включённом env-флаге отправки не будет.

После выбора списка требуется новая проверенная ревизия helper и wrappers с новыми SHA. build.py намеренно запрещает незаметно превратить этот пустой пакет в разрешённую рассылку редактированием одного JSON.

Helper отклоняет событие другого клуба до чтения участников и пересекает результат существующего pickDmRecipients с серверным списком. Сохраняются active/end_date, send_notif, исключение отправителя, отсутствие профиля, общий allowlist и прежний fetchSubs/deliver/VAPID. Запрос не может передать клуб или список получателей вместо серверной политики. Содержимое push прежнее обезличенное: «Новое сообщение в клубе» / «Новый пост в клубе», переход `/club/?club=737b8824-88b8-4cee-b50b-3f4ed3b59683`.

`index.ts` при установке НЕ меняется: прежние события, глобальные флаги и env-gate сохранены побайтно. Новый файл конфигурации, таблица, сервис, очередь или механизм синхронизации не добавляется. Frontend и service worker не меняются.

## Пакет mg-deploy

- `status`: SHA handler/helper, два состояния триггеров, присутствие/значение только клубного boolean flag и безопасные Compose labels (путь/служба); без секретов и записей.
- `install`: точное совпадение текущих index/helper и функции, club flag=false и triggers D, root-only backup `/var/lib/mg-deploy/club-push-pilot-20261126`, замена только helper. При ошибке проверки восстанавливает прежний helper. Глобальный env сравнивается до/после, не изменяется. При успехе `INSTALLED_DISABLED`.
- `enable`: сейчас завершается `STOP=recipient_approval_required` ДО любых действий. В будущей ревизии также потребует точно установленного helper, действующих подписок/настройки send_notif выбранных аккаунтов, исходных trigger definitions и **уже правильно переданного PUSH_CLUB_ENABLED=true**. Затем изменит только два существующих triggers, добавив WHEN на один club UUID. При ошибке после попытки enable вызывает клубное отключение. Никакого тестового сообщения скрипт не создаёт.
- `disable`: выключает только два новых клубных триггера, затем заменяет только строку клубного gate в известном index на константу false и перезапускает Edge Runtime. Это закрывает новые входящие club callbacks даже при оставшемся true в env. Прежние типы push сохраняются. При неизвестном index не перезаписывает его; сообщает STOP после отключения триггеров — тогда остановка уже поставленных callbacks требует действий администратора. Уже отправленные/исполняющиеся уведомления невозможно отозвать.

Install/disable требуют restart общего supabase-edge-functions для обновления worker cache. Файлы других функций не меняются, но возможна краткая недоступность всего Edge Runtime. Это действие сейчас НЕ выполнялось.

После emergency disable нельзя просто снова запустить enable: gate намеренно зафиксирован false. Перед возобновлением нужна сверенная ревизия возврата исходного env-gate при уже ограниченном helper, выключенных triggers и повторном согласовании. Не восстанавливать широкий старый helper при включённом клубном gate.
