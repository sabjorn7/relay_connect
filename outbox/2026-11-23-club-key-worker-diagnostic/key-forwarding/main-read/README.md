# Необходимое чтение фактического main/index.ts

**Это read-only пакет, НЕ установщик исправления.**

Проверено: mgdeploy имеет только NOPASSWD-доступ к `/usr/local/sbin/mg-deploy`. Прямого административного доступа к Docker и закрытым метаданным нет. Одобрение ранее подготовленных скриптов не распространяется на этот SHA. Подменять одобренные файлы или самостоятельно менять approved.sha нельзя.

Скрипт в `/home/mgdeploy/staging/meetguru-club-main-read-20261123.sh`.

SHA-256:

```text
3a436a095bd422a7b5c8747b818355835ddad4e79b107d20698ed576db8b706f
```

## Действие администратора

1. Просмотреть исходники и сверить SHA на сервере:

```bash
sha256sum /home/mgdeploy/staging/meetguru-club-main-read-20261123.sh
```

2. После проверки одобрить этот SHA через существующий `/etc/mg-deploy/approved.sha`.
3. Выполнить:

```bash
sudo /usr/local/sbin/mg-deploy meetguru-club-main-read-20261123.sh
```

4. Передать полученный JSON. Он содержит только SHA исходного кода и строго ограниченные фрагменты объявления servicePath/envVars и вызова worker. Произвольные строковые значения, комментарии, env, токены, секретный файл и полный исходник не выводятся. Если код не соответствует распознаваемой форме, фрагмент не экспортируется; вместо предположительной замены потребуется дальнейшее закрытое чтение администратором.

## Границы

Скрипт только читает Docker mounts, метаданные успешного релиза и два исходных файла. Не читает содержимое или хеш файла ключа. Не пишет файлы, не перезапускает runtime, не вызывает Edge Function, RPC или Prodamus. Сам mg-deploy выполняет штатное копирование одобренного скрипта и ведение собственного журнала.

`restricted_fragments_complete=true` означает распознание узких фрагментов, а не аудит всего main/index.ts. Итоговый установщик должен быть привязан к полученному SHA и сохранять остальные байты исходника, включая авторизацию и маршрутизацию.

## Что будет подготовлено после чтения

Только main/index.ts (точечное подключение) и main/club-key-env.mjs. checkout-pay-link уже читает env; его ключ, права, SQL, n8n и frontend не меняются. Общий main требует последующей проверки: другие worker должны получать ровно прежние envVars, авторизация и маршрутизация — остаться побайтно неизменными вне точки подключения.

Установочный пакет и отдельный rollback будут сформированы только после сверки реального кода. Они должны сохранять закрытую резервную копию и SHA, отказываться от перезаписи неожиданных изменений и восстанавливать точный прежний main. Будущий перезапуск общего Edge Runtime потребует отдельного согласования и кратковременно затронет доступность всех Edge Functions. Сейчас перезапуск не выполняется.
