# Установка временной диагностики через mg-deploy

**Только подготовка. Установщик и откат не запускались. Одобрение SHA — только администратором.**

Файлы размещены на sb в `/home/mgdeploy/staging/`.

## Проверка и одобрение

```bash
sha256sum /home/mgdeploy/staging/meetguru-club-key-diagnostic-{install,rollback}-20261123.sh
```

Ожидаемые SHA:

```text
7c98b36f1862c59cdad60563aa55e712bd1b0165d4fba60980c11a70a1b7acde  meetguru-club-key-diagnostic-install-20261123.sh
a4882266cf261ac154baefec7e79e17f28d8ab518f08f524b5448c80322f6f01  meetguru-club-key-diagnostic-rollback-20261123.sh
```

Администратор проверяет исходники и одобряет оба SHA существующим механизмом `/etc/mg-deploy/approved.sha`. Самостоятельного добавления SHA установщик не выполняет.

## Что разрешается запуском

1. Проверка успешного выпуска `/var/lib/mg-deploy/club-release/install-20261123T195707Z-161238/state.json`, фактического mount и исходного SHA `index.ts`.
2. Закрытая root-only резервная копия только `index.ts` и его метаданных в `/var/lib/mg-deploy/club-key-diagnostic/20261123-v1/`.
3. Атомарная замена только `checkout-pay-link/index.ts` с сохранением его владельца и режима.
4. **Перезапуск только общего контейнера `supabase-edge-functions`. Это кратковременно затрагивает доступность всех Edge Functions, но не меняет их код.**
5. Ограниченная анонимная проверка POST `{}` с ожидаемым 401; ни пользователя, ни заказа, ни платежа не создаёт.
6. Чтение последних журналов и вывод только JSON `club_key_load_v1` после строгой проверки полей и значений. Сырые журналы не выводятся и не сохраняются.

Файл ключа, его значение и хеш не читаются административным установщиком. Ключ читает только диагностируемый worker штатным путём. SQL, n8n, frontend, nginx и остальные исходники не изменяются.

## Запуск после одобрения

```bash
sudo /usr/local/sbin/mg-deploy meetguru-club-key-diagnostic-install-20261123.sh
```

Успешный результат: диагностический JSON, `DIAGNOSTIC_INSTALLED=True`, `AUTH_SMOKE=401`, `NO_ORDERS_OR_PAYMENTS=True`, путь BACKUP.

`DIAGNOSTIC_INSTALLED=True` означает успешную установку диагностики, **а не восстановление оплаты**. Передать только JSON с `event=club_key_load_v1`; не отправлять env, файл ключа или полные журналы.

При расхождении исходного SHA установка прекращается до замены файла. При ошибке после замены выполняется попытка автоматического восстановления исходного index.ts с перезапуском Edge и проверкой 401. Если выводится `AUTO_ROLLBACK_FAILED=True`, остановиться и передать администратору: автоматическое восстановление не подтверждено. При SIGKILL/отключении сервера обработчик ошибок не гарантируется — использовать отдельный rollback.

Повторный запуск уже установленного патча не перезапускает контейнер. Наличие старого каталога резервной копии при исходном файле требует ручного разбора; установщик ничего в нём не перезаписывает.

## Отдельный откат после одобрения его SHA

```bash
sudo /usr/local/sbin/mg-deploy meetguru-club-key-diagnostic-rollback-20261123.sh
```

Проверяет SHA резервной копии и текущего index.ts, возвращает только исходный index.ts, перезапускает Edge Runtime и проверяет 401. Не удаляет заказы, подписки, SQL, callback, файл ключа или резервную копию. При неизвестных изменениях index.ts отказывается их перезаписывать.

## Проверки пакета

- 17 тестов worker-диагностики PASS на синтетическом Deno API.
- 12 тестов административного кода PASS: строгий фильтр журналов, приватность, отказ без root, неизвестный baseline/rollback, symlink и локальная атомарная замена.
- `bash -n`, синтаксис встроенного Python и отказ от запуска без root — PASS.
- Проверено без запуска Docker, root-скриптов или production-тестов. Реальный Edge Runtime будет проверен только после одобренной установки.
