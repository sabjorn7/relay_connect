Это выравнивание инструментов вложений, не замена legacy-композера. Его поле текста, условное появление текстовой кнопки отправки, desktop-аватар и существующая кнопка загрузки фотографии сохранены. ## Повторение

В отдельной чистой копии приложения с указанной базой и установленными проектными зависимостями:

```sh
git apply --unidiff-zero --check /path/to/frontend.diff
git apply --unidiff-zero /path/to/frontend.diff
# Скопировать три файла tests из пакета в tests отдельной копии.
./node_modules/.bin/vite build -l warn
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/club-composer.browser.mjs
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/club-composer-full.browser.mjs
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/local-regression-group-chat-authors.browser.mjs
```

Проверено на Node 24.14.0, установленном Playwright, локальном Chrome и WebKit. Зависимости не добавлялись. Тесты используют установленный Chrome по macOS-пути; на другой ОС нужен доступный Chromium executable. `frontend.diff` намеренно без контекстных строк; обязательно `--unidiff-zero`. Before/after SHA каждого исходника — `manifest.json`.

## Публикация и откат

Данный пакет не разрешает публикацию. После отдельного согласования сверить main и SHA исходников; применить только два frontend-файла, повторить build и тесты, выпустить штатным Deploy App. Серверные операции и переключение capability не требуются.

До коммита обратимость проверяется `git apply --unidiff-zero --reverse --check frontend.diff`. Откат только этого изменения: обратный diff двух файлов отдельным релизным коммитом через штатный Deploy App после согласования. Данные сообщений/вложений не затрагиваются. Если main изменится, не перезаписывать чужие изменения — сначала сверить diff.

## Ограничения и риски

CSS привязан к существующим desktop/mobile UUID WeWeb. После нового экспорта с изменением структуры композера нужны те же маршрутные проверки. Используются CSS grid/:has/display:contents, проверенные в доступных Chrome/WebKit; старые браузеры без :has не проверены. Исходные legacy-обработчики фотографий/текста сохранены. Достоверность server-side прав, push и бизнес-логики этой UI-задачей не переоценивалась и не менялась.

Готов к рассмотрению diff и согласованию frontend-публикации. Для подтверждения успешной записи физическим Safari остаётся отдельная ручная проверка на устройстве.
