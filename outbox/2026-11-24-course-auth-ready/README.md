# MyCourse: ложный переход на /login после релиза Auth

Статус: локальное исправление готово к согласованию. Production не менялся, Deploy App не запускался. Ветка локального кандидата: fix/course-auth-ready-20261124, база 1d8364f7721cb0e9eeefaad815f1d1469af6ead7. Коммит приложения не создан.

## Подтверждённая причина

MyCoursePage.vue: load() читает readStoredSession()/authCookieUser() синхронно и сразу перенаправляет на /login при null. После релиза headerAccount возвращает только подтверждённый snapshot плагина (_getUser), а не произвольный localStorage/cookie. Snapshot может ещё отсутствовать, пока SDK восстанавливает сессию или загружаются роли/профиль. MyCourse не ожидает SDK.

Тест настоящих MyCoursePage.vue и headerAccount.js воспроизводит redirect в Chrome/WebKit при пустом snapshot и действующей синтетической SDK-сессии. Запись сессии остаётся в storage; этот путь не вызывает signOut. Это подтверждает ошибочный переход на вход, а не удаление токенов. Реальное устройство пользователя не обследовалось; нельзя утверждать, что иных причин нет.

## Минимальное исправление

Изменён один продуктовый файл: src/_front/views/MyCoursePage.vue.

- Дождаться getSession() единственного существующего SDK перед решением guest → login.
- При подтверждённом session=null сохраняется переход на вход.
- При временной ошибке или неподтверждённой/истёкшей сессии защищённое содержимое не загружается; появляется сообщение с ручной кнопкой «Повторить».
- Проверки покупки, срока доступа, запретов уроков и существующая загрузка курса не изменены.
- Сериализация, SDK, cookies, logout, backend, SQL/RLS не менялись. Новых таймеров/автоматических повторов нет.
