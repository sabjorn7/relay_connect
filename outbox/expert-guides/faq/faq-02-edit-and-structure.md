# FAQ: как редактируется сейчас + самый простой способ для владельца + структура категорий

## 1. Как FAQ редактируется сейчас
- Контент **зашит в код** `src/_front/views/FaqPage.vue` (объект `CONTENT`). Нет ни таблицы в БД, ни админки, ни WeWeb-CMS.
- Чтобы изменить вопрос/ответ — нужно **править файл и делать деплой** (git push → CI). **То есть нужен разработчик.** Без деплоя текст не поменяется.

## 2. Самый простой способ для владельца править FAQ без разработчика (ПРЕДЛОЖЕНИЕ, пока не делаю)
Рекомендую перевести FAQ в **таблицу БД + простой экран редактирования**, тогда владелец добавляет/правит вопросы сам, без кода и деплоя:

- Таблица `public.faq` с полями: `id, audience ('students'|'experts'), category, question, answer, sort, published, updated_at`.
- Страница `/faq` читает активные строки из таблицы (как уже сделано для других разделов) вместо хардкода.
- Редактирование — одним из двух способов (на выбор):
  - **(A) Вкладка «FAQ» в `/superadmin`** — форма «добавить/изменить/скрыть вопрос», порядок перетаскиванием. Правки видны на сайте сразу, без деплоя. (Самый удобный для владельца, но требует разработки экрана + RPC.)
  - **(B) Минимальный вариант без новой админки** — владелец правит строки прямо в **Supabase Studio** (таблица `faq`), страница подхватывает. Дешевле в реализации, но править в Studio менее дружелюбно.
- Доступ на запись — только admin/суперадмин (как у промокодов/комиссии), таблица под RLS.

⚠️ Это изменение **сайта и БД** (миграция + правка фронтенда). **Ничего не делаю, пока не дашь ОК.** Текущая задача — только описать и предложить.

## 3. Предлагаемая структура категорий (две аудитории)
На странице имеет смысл два верхних раздела-таба: **«Ученикам»** и **«Экспертам»**, внутри — категории:

**Ученикам**
1. Оплата и доступ
2. Курсы и обучение
3. Возврат денег
4. Эфиры
5. Клубы (подписки)
6. Бонусы и промокоды
7. Профиль и пароль

**Экспертам**
1. Создание курса
2. Цены и скидки
3. Выплаты и комиссия
4. Эфиры
5. Клуб
6. Мероприятия
