# FAQ CMS — фронтенд-дифф на ревью (2026-10-30)

Файл: `2026-10-30_faq-cms-frontend.diff` (в корне outbox). Сгенерирован из изолированного
git-worktree, созданного от **origin/main** `meetclone` (коммит `2937338...`, «отзывы
course.comment сортируются по дате»), а не от рабочей ветки `feat/streams-ended` — чтобы не
смешиваться с текущей работой на той ветке. После генерации диффа worktree полностью
откачен и удалён (`git worktree remove`); сам `meetclone` нигде не тронут и не закоммичен —
только прочитан для сверки путей/стилей. **Ничего не запушено и не задеплоено в `meetclone`.**

Применить этот дифф к `meetclone` и задеплоить может только владелец, и только по явному ОК,
вне эфиров и оплат, ночью по МСК (см. §г в `faq-04-cms-plan.md`). Миграцию
(`2026-10-30_pending_faq_table.sql`) владелец применяет сам — этот дифф предполагает, что
таблица `faq` уже существует с описанной RLS, но безопасен и без неё (см. фолбэк ниже).

## Что в диффе (6 файлов)

- `src/_front/views/FaqPage.vue` — чтение из `public.faq` (audience/lang), вкладки
  «Ученикам»/«Экспертам», поиск, DOMPurify на `answer`. Если строк нет/ошибка/таблицы ещё
  нет — показывается **прежний хардкод `CONTENT` без изменений**, без вкладок и поиска (они
  рендерятся только когда есть реальные строки из БД — у старого контента нет деления по
  аудитории, подменять поведение не стал). Добавлена защита от гонки запросов при быстром
  переключении вкладки/языка (`loadSeq`).
- `src/_front/router.js` — маршрут `/faq/guides` (лениво, как `CoursesManagePage`/
  `MyFinancePage`), брендновый путь без `wwPath`.
- `src/_front/views/FaqGuidesPage.vue` (новый) — страница инструкций, только RU, якоря
  `#course #stream #event #club #money`. Контент хардкодом, составлен по уже сверенным по коду
  инструкциям из `expert-guides/instructions/01..06` плюс раздел «Со-ведущие» для `#stream`.
- `src/_front/views/CoursesManagePage.vue`, `StreamsPage.vue`, `MyFinancePage.vue` — по одной
  ссылке **«Как это сделать?»** на `/faq/guides#course` / `#stream` / `#money` соответственно.

## Решения владельца, применённые как есть

1. Якоря: `#course #stream #event #club #money` — мероприятия и клуб включены в
   `FaqGuidesPage.vue` (с явной пометкой-предупреждением там, где по коду доступ сейчас
   ограничен: мероприятия — только `adv@meetgu.ru`; создание клуба в приложении отсутствует).
2. DOMPurify для `answer`: `ALLOWED_TAGS` — `a, strong, em, b, i, br, p, ul, ol, li`;
   `ALLOWED_ATTR` — `href, target, rel`; хук `afterSanitizeAttributes` принудительно ставит
   `rel="noopener noreferrer"` на каждую `<a>`, независимо от того, что ввёл админ в Studio.
3. Контент гайдов — хардкод в компоненте (без таблицы под гайды, без markdown-рантайма).
4. `FaqGuidesPage.vue` — только русский, без переключателя (в отличие от `FaqPage.vue`, где
   РУС/ENG остаётся как было).

## Не сделано в этом диффе (ждёт макета/отдельного решения)

- **Визуальные схемы экранов** — не включены. По просьбе владельца они берутся из макета,
  который владелец пришлёт отдельно, а не из скриншотов `screens/`; пока на странице только
  текст (заголовки/шаги/заметки). Когда макет придёт — понадобится отдельная правка вёрстки
  `FaqGuidesPage.vue` (эта не трогает структуру данных `GUIDES`, только шаблон/стили).
- CSS страницы `/faq/guides` и трёх ссылок «Как это сделать?» — продублирован точечно
  (переиспользован акцентный цвет каждой страницы: `#2e6fd6` на `/faq*`, `var(--blue)`/
  `#5495f3`/`#5495F3` на остальных трёх, по месту), не вынесен в общий файл — чтобы дифф
  оставался «вставить и готово», без правки общих стилей.

## Как проверить до деплоя (чек-лист для ревьюера)

- `npx eslint src/_front/views/FaqPage.vue src/_front/views/FaqGuidesPage.vue
  src/_front/views/CoursesManagePage.vue src/_front/views/StreamsPage.vue
  src/_front/views/MyFinancePage.vue src/_front/router.js` — не прогонялся здесь (нет
  `node_modules` в одноразовом worktree, которым генерировался дифф).
- Применить диффом в реальный чекаут с установленными зависимостями, собрать (`npm run build`),
  посмотреть `/faq` и `/faq/guides` глазами — особенно пустую БД (должен быть виден ТОЛЬКО
  старый контент, без вкладок/поиска) и наполненную (после того как владелец применит миграцию
  и внесёт тестовую строку).
