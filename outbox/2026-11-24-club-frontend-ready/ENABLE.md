# Отдельное включение после UI — сейчас ничего не выполнять

## Файлы и голосовые

1. Согласовать тестовый клуб/участника и пользовательские проверки (включая Safari microphone).
2. После UI выполнить server-next/attachments-enable.sql административным механизмом. Меняется только определение уже установленной capability RPC; членство/права/подписки не меняются.
3. Проверить от авторизованного участника capability=true, upload только в club-chat-private, отправку RPC, signed URL, голосовую запись и удаление сообщения. Не выполнять произвольные новые операции от чужого пользователя.
4. При ошибке capability снова false через disable.sql. Ранее выданная signed URL может действовать до 60 секунд.

## Два club push события — только ограниченный пилот

1. Через штатный административный mg-deploy отдельно опубликовать только Edge changes из 9a698cf (web-push-send/index.ts + club.mjs). Сначала сверить фактическую серверную версию с базой и сохранить её. Deploy App Edge Functions не публикует.
2. Убедиться в выключенных DB triggers. Установить PUSH_CLUB_ENABLED=true штатной защищённой конфигурацией этой Edge Function. Пока triggers D, автоматических club событий нет. Не менять глобальный PUSH_ALLOWLIST: он общий с работающими уведомлениями. Существующие opt-out/send_notif сохранить.
3. Выбрать контролируемый клуб с заранее согласованными получателями (1–10), а не включать оба триггера для всех клубов. server-next/push-pilot-enable.sql добавляет WHEN только этого club UUID и проверяет верхнюю границу текущих подписчиков. Это дополнительная точечная настройка пилота, требует отдельного согласования. Никакого изменения членства не выполняет.
4. Создать согласованное тестовое сообщение и опубликованный пост; проверить экран устройства и переход /club, отсутствие текста/имён/названия клуба в push. Редактирование не должно отправлять повтор. Проверить opt-out. Не выполнять эти действия без разрешения на smoke/уведомления.
5. После проверки отключить два triggers; оценить результат до дальнейшего включения. SQL-проверка числа получателей не является постоянным rate cap: тестовый клуб должен оставаться контролируемым.

Оба trigger могут оставаться выключенными, даже когда вложения уже включены. И наоборот — эти этапы не сцеплены. Массовое включение оригинальным enable-after-approval.sql из предыдущего пакета НЕ является частью этого плана.
