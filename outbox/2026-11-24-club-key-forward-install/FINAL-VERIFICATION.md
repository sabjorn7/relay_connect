# Финальная проверка подтверждения установки

Диагностика вызывается при старте worker до обработки анонимного запроса:
- [index.ts, строки 45–50](../2026-11-23-club-key-worker-diagnostic/index.ts#L45): выбор источника, console.info, затем Deno.serve.
- [handler.mjs, строки 25–31](verification-fixtures/handler.mjs#L25): отсутствие Authorization приводит к HTTP 401 до Auth/API/RPC/Prodamus.

SHA диагностического index: `a1aa4e054a18418568959113d83edd6395a8e3c2480b73222056a93779c2dac5`. Тестовые копии handler и clubPayment сверены с payload установленного релизного пакета. Worker-start тест исполняет фактический диагностический index с этим обработчиком и синтетическим Deno; реальные сети не используются.

Запись однократная: повторный запрос в тёплый worker не создаёт новую запись. Первоначальная проверка (4 чтения последних 200 строк) могла принять недоступную или вытесненную запись за отказ ключа и откатить исправную установку. Это подтверждённый риск проверки, не наблюдавшийся production-инцидент.

## Минимальное исправление r2

Изменён только контроль результата в admin.py и повторная проверка уже установленного состояния:
- сохраняется строгий HTTP smoke: 401, маркер версии обработчика и JSON unauthorized;
- до 10 чтений последних 2000 строк с паузами по секунде, начиная с StartedAt текущего контейнера;
- положительная диагностическая запись подтверждает успех;
- явная отрицательная запись при первичной установке вызывает прежний rollback;
- отсутствие читаемой записи или границы времени после успешного smoke: exit 2, VERIFICATION_INCONCLUSIVE=True, KEY_FORWARDING_CONFIRMED=False, AUTO_ROLLBACK_NOT_RUN=True. Успех не объявляется. Администратор проверяет журналы; допустимо повторить тот же установщик — установленное состояние проверяется без рестарта;
- при повторной проверке установленного состояния явная отрицательная запись даёт exit 1; откат выполняется отдельным скриптом после административного решения.

Проверки SHA, backup, точечная правка main, изоляция ключа, HTTP smoke и реализация rollback сохранены. Функции rollback, patch_main, unchanged, discover, read, save, replace, secure_dir, smoke и diagnostic_records идентичны исходному коммиту a5ea60d на уровне AST.

## Проверки

42 PASS: helper 8, patcher 9, admin/rollback 11, worker-start 2, verification 12. Дополнительно bash -n, синтаксис встроенного Python, bootstrap и отказ запуска без root. Новые тесты подтверждают отсутствие отката и сообщения об успехе при неопределённой проверке, откат при отрицательной диагностике и успешное завершение при положительной.

Production не изменялся, серверные скрипты не запускались, сервисы не перезапускались, платежи и заказы не создавались. Реальное исполнение helper в Edge Runtime остаётся проверкой при отдельно согласованной установке. Отсутствие диагностической записи после успешного 401 не подтверждает передачу ключа: при exit 2 нельзя объявлять выпуск завершённым.

## Запуск и откат

Использовать только r2-файлы и новые SHA из [SHA256SUMS](SHA256SUMS). Полная процедура копирования в staging, одобрения обоих SHA и запуска через mg-deploy — в [README](README.md#порядок-запуска-после-отдельного-согласования). Автоматически SHA не одобрять. Старые файлы не запускать.

Установка и откат перезапускают общий Edge Runtime и кратковременно затрагивают остальные функции. Откат восстанавливает исходный main и возвращает прежнюю ошибку оплаты клуба. Резервная копия сохраняется.
