# Исправление передачи ключа checkout-pay-link через main worker

**Использовать только скрипты `-r2.sh`. Исходные скрипты сохранены для истории.**

**Готовый пакет для административного согласования. На production не загружен и не запускался.**

## Что меняется

1. В `main/index.ts` заменяется только shorthand-свойство `envVars` в единственном вызове `EdgeRuntime.userWorkers.create()`:

```diff
- envVars
+ envVars: await (await import("./club-key-env.mjs")).clubWorkerEnv(servicePath, envVars)
```

Это фрагмент точной операции, не шаблон всего main. Установщик разбирает фактический файл и сохраняет побайтно всё вне диапазона свойства. Дополнительные импорты/объявления в main не добавляются. Все остальные параметры вызова, маршрутизация и JWT-код остаются прежними.

2. Добавляется `main/club-key-env.mjs` — уже подготовленный helper без изменений. Доверенный main читает существующий `.prodamus-key.json`; отдельная копия envVars с ключом передаётся только при servicePath `/home/deno/functions/checkout-pay-link`. Для других функций возвращается исходный объект envVars, файл ключа не читается. Глобальное окружение не изменяется.

**Не меняются** checkout-pay-link/index.ts, его текущая диагностика, handler, SQL, n8n workflows, frontend, Prodamus, значение ключа и права 0400/root:root.

## Жёсткая привязка к исходникам

- main/index.ts: `c0ea2ba6c68ae162f27516b384eaa722665e8b64df839f5a3e4901df55e47d1a`
- checkout-pay-link/index.ts: `a1aa4e054a18418568959113d83edd6395a8e3c2480b73222056a93779c2dac5`

Проверяется один вызов, один object argument и ровно шесть shorthand-параметров в подтверждённом порядке: servicePath, memoryLimitMb, workerTimeoutMs, noModuleCache, importMapPath, envVars. При любом расхождении — отказ до изменения исходников. Установщик не пытается адаптировать неизвестную версию.

Полного production main локально нет. Безопасность точечной операции обеспечивается подтверждённым SHA, структурной проверкой фактического файла перед записью и заменой только диапазона envVars. Синтаксис полученного main проверяется до замены. Это не предполагаемая замена файла шаблоном.

## Порядок запуска после отдельного согласования

1. Проверить исходники пакета. Скопировать только два .sh в `/home/mgdeploy/staging/` под владельцем mgdeploy, не перезаписывая существующие файлы.
2. Сверить SHA и синтаксис:

```bash
sha256sum /home/mgdeploy/staging/meetguru-club-key-forward-{install,rollback}-20261124-r2.sh
bash -n /home/mgdeploy/staging/meetguru-club-key-forward-install-20261124-r2.sh
bash -n /home/mgdeploy/staging/meetguru-club-key-forward-rollback-20261124-r2.sh
```

3. Администратор одобряет оба SHA существующим механизмом `/etc/mg-deploy/approved.sha`. Скрипты не добавляют SHA самостоятельно.
4. Запустить:

```bash
sudo /usr/local/sbin/mg-deploy meetguru-club-key-forward-install-20261124-r2.sh
```

### Действия установщика

- Чтение фактического mount и сверка с успешным релизом `/var/lib/mg-deploy/club-release/install-20261123T195707Z-161238/state.json`.
- Проверка SHA/структуры/syntax, отсутствия постороннего helper, безопасных каталогов и symlink.
- Root-only backup: `/var/lib/mg-deploy/club-key-forwarding/20261124-v1/main.before.ts` и `metadata.json`. Проверка SHA копии до замены; сохраняются владелец и режим main.
- Создание helper и атомарная замена main. Файл ключа установщик не открывает и не хеширует; проверяются только неизменность его метаданных и ожидаемые права.
- **Один перезапуск общего контейнера supabase-edge-functions.** Это кратковременно затрагивает доступность ВСЕХ Edge Functions.
- Анонимный POST `{}` к checkout-pay-link: ожидается 401. Нет пользователя, заказа или обращения к Prodamus.
- Чтение безопасной диагностической записи именно после нового старта контейнера. Успех требует `env_present=true`, `env_nonempty=true`, `env_error=null`, `source=env`.
- Проверка неизменности checkout исходников и метаданных ключа.

`file_error=PermissionDenied` может остаться: временная диагностика по-прежнему отдельно проверяет файл внутри sandbox. Теперь рабочий источник ключа — `env`.

Ожидаемый итог: `KEY_FORWARDING_INSTALLED=True`, `AUTH_SMOKE=401`, `KEY_UNCHANGED=True`, `NO_ORDERS_OR_PAYMENTS=True`, SHA изменённого main и BACKUP.

**Это подтверждает передачу ключа, не реальное получение ссылки Prodamus.** Проверка авторизованного пути без списания — отдельный следующий шаг. Установщик не создаёт заказов, подписок и платежей.

## Откат

При подтверждённой ошибке после начала замены установщик пытается выполнить откат автоматически. Исключение: после успешного HTTP smoke отсутствие доступной диагностической записи означает неопределённый результат (exit 2), а не отказ передачи ключа. В этом случае автоматического отката нет, успех не объявляется; требуется ручная проверка. См. [финальную проверку](FINAL-VERIFICATION.md). Возможен дополнительный перезапуск Edge Runtime для восстановления. При SIGKILL/отключении сервера автоматический откат не гарантирован.

Отдельный одобренный rollback:

```bash
sudo /usr/local/sbin/mg-deploy meetguru-club-key-forward-rollback-20261124-r2.sh
```

Порядок: проверить SHA backup и текущих main/helper, неизменность защищённых файлов/ключевых метаданных → восстановить точный исходный main с прежними владельцем и режимом → перезапустить Edge Runtime → подтвердить 401 → удалить только установленный этим пакетом helper с совпадающим SHA.

При неизвестных изменениях отказ до перезаписи. При неуспешной проверке после перезапуска helper остаётся для ручного восстановления. Резервная копия не удаляется. Данные, подписки, заказы и ключ не меняются. **Откат возвращает прежнее состояние, включая известную ошибку 503 оплаты клуба.**

Если выводится `AUTO_ROLLBACK_FAILED=True`, остановиться: возврат состояния не подтверждён, требуется административная проверка. Не повторять установку и не удалять backup вручную.

Повторная установка обнаруживает ранее установленное состояние по SHA и повторяет HTTP smoke и проверку диагностических записей без перезапуска. При отсутствии записи — exit 2; при явной отрицательной записи — exit 1 и ручной откат отдельным скриптом, поскольку это уже установленное состояние. Существующая резервная копия при другом состоянии требует ручной проверки.

- 11 admin-тестов PASS: baseline drift, повреждённый backup, неизвестный main/helper, последовательность rollback, отказ smoke, symlink, атомарная замена, приватность диагностического вывода.
- bash -n, Python syntax, node --check helper, отказ без root и проверка встроенного bootstrap PASS.

- 2 worker-start-теста PASS: реальный диагностический index и обработчик, порядок log → serve → 401, отсутствие сетевых вызовов и повторного startup-лога.
- 12 verification-тестов PASS: задержка/отсутствие логов, отказ чтения, отрицательная диагностика, ветви успешной установки и отката.

Всего **42 теста PASS**. Это локальные синтетические проверки. На реальном Edge Runtime 0.1.0 / Deno 1.45.2 пакет ещё не запускался. Main worker должен иметь доступ к серверному файлу; это будет подтверждено записью source=env, при явном отрицательном результате первичная установка откатится; при недоступной записи — остановится с exit 2 без подтверждения успеха и без автоматического отката. Риск остальных функций — кратковременная недоступность при общем перезапуске и общий загрузчик main; для снижения риска проверяются синтаксис, целостность, узкая правка, изоляция окружений и анонимный smoke.
