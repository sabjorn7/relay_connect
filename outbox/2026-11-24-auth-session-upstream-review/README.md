# Сохранение авторизации: проверка upstream SDK

Статус: НЕ ГОТОВО к публикации. Production и продуктовые файлы не менялись.

[Отчёт](REPORT.txt). Это диагностический пакет, не установщик и не production-патч.

## Локальное воспроизведение

Node.js 24 (проверено 24.14.0):

```sh
npm ci --ignore-scripts --no-audit --no-fund
node terminal-login-race.mjs
node stale-event.mjs
```

Все Auth/HTTP данные синтетические; тесты не обращаются к production. Установка npm требует сети только для зависимостей.

Первый тест подтверждает сохранность B после терминального refresh A (400/401) и последующий logout B. Второй тест намеренно подтверждает ОСТАВШИЙСЯ дефект: storageUser=B, viewUser=null. Его успешный exit означает воспроизведение ошибки, а не готовность исправления.

Fixtures — копии существующего локального кандидата. Единственная адаптация authRecovery: импорт класса AuthRetryableFetchError из установленного auth-js вместо реэкспорта supabase-js. Это НЕ продуктовое изменение. confirmedSession исполняется в VM с синтетическими зависимостями. Проверяются реальные методы SDK, но не браузерный планировщик.

Незавершённый refresh-matrix не включён в проверенные тесты. Полная матрица Chrome/WebKit, PWA, VK, email и checkout ещё не повторялась. Продуктового исправленного diff в этом пакете нет: пока получено доказательство для выбора следующего безопасного изменения.
