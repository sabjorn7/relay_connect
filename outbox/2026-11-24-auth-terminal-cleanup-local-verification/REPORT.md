## Что проверено

Применён без изменений `sdk-terminal-cleanup.proposed.diff` к отдельной копии исходников SDK. CJS и ESM собраны TypeScript 5.8.3 по конфигурациям официального тега v2.119.2. Получен локальный npm tarball `2.119.2-mg.terminal-test.1`; он установлен npm override только в отдельный архив проекта. Ручных изменений node_modules и runtime monkey-patch нет. Tarball не опубликован.

Причина исходного сбоя: проверка сохранённой сессии A и её удаление разделены асинхронным промежутком. В нём может быть записана B. Предложенный патч объединяет проверку идентичности и удаление сессии с операциями записи под общей блокировкой. Терминальный ответ применяется к соответствующему refresh token. Настоящий logout остаётся безусловным. Штатная серверная проверка токенов не обходится.

Node-reproducer обращается к внутреннему методу только для воспроизведения; новый браузерный gap-тест вызывает публичные refreshSession/signInWithPassword/signOut и использует поддерживаемый storage adapter для детерминированной задержки.

В 409/429/500 браузерный тест наблюдал по два запроса до восстановления. Offline — шесть запросов в ограниченном сценарии теста, включая поведение SDK. Это не измерение production-трафика и не доказательство верхней границы всех внутренних повторов SDK.

## Ограничения и риски

- NOT TESTED: физический iPhone/Android, установленный PWA после реальных суток/недели сна. sleep-week использует синтетически просроченный токен.
- NOT TESTED: реальные серверы Auth и VK; реальные покупки намеренно исключены. Отдельные email/VK и checkout suites запускались в Chrome, не WebKit.
- NOT TESTED: смешанные вкладки со старой и исправленной версией SDK. Старый SDK не участвует в новой блокировке; безопасное постепенное обновление требует отдельного решения перед выпуском.
- Известное ограничение предложения: браузер без Web Locks получает ошибку записи, небезопасного fallback нет. Поддержку таких устройств нельзя объявлять подтверждённой.
- NOT TESTED: принудительное убийство вкладки внутри блокировки и все пути timeout новой write-lock. Тест lock-15s удерживает прежнюю SDK-блокировку и доказывает отсутствие блокировки публичного интерфейса в данном сценарии, но не заменяет проверку новой write-lock.
- Это поддерживаемый нами исходный патч зависимости, а не официальный upstream-релиз. При обновлении SDK нужна повторная проверка diff и всей матрицы.
- Локальная среда Node 24.14.0. CI остаётся Node 20; требование новой зависимости Node >=22 не устранено. Изменение CI отдельно не согласовано и здесь не применялось.
