## Что вернётся

- фактические вызовы EdgeRuntime.userWorkers.create(), включая computed property notation;
- объявления аргументов/объекта настроек и их синтаксические зависимости;
- связанные присваивания и изменения объекта envVars;
- номера строк и безопасные нормализованные фрагменты;
- SHA исходного main и checkout index, без хеша файла ключа.

Все произвольные строковые значения и части шаблонных строк редактируются; выражения ${...} сохраняются структурно. Числа заменяются маркером, regex — /REDACTED/, комментарии удаляются. Неизвестные идентификаторы получают стабильные внутри отчёта псевдонимы id_001 и т. п. Сохраняются только фиксированные известные API-имена и несколько публичных строк: каталог функций, имя checkout-pay-link, имена servicePath/envVars/PRODAMUS_SECRET_KEY. Значения окружения не запрашиваются. Ключевой файл не открывается.

Фрагменты предназначены для ручной проверки структуры, а не автоматического применения патча. Анализ не доказывает разрешение областей видимости или полный control flow. При нескольких определениях показываются кандидаты с номерами строк. Ограничения: 5 уровней зависимостей, до 30 определений, 20 присваиваний, 10 вызовов и 12000 символов фрагмента; усечение явно отмечается.

## Как работает без установки инструментов

Скрипт через Docker inspect читает только mounts Edge Runtime и сверяет mount с метаданными успешного релиза. Затем читает main/index.ts и checkout-pay-link/index.ts.

Встроенный @babel/parser 7.29.7 взят из уже установленной локальной зависимости; исходник и MIT-лицензия включены в vendor. Парсер и анализатор сверяются по SHA. В существующем контейнере `supabase-n8n-1` запускается **отдельный одноразовый процесс** `node` от пользователя `node` с очищенными NODE_OPTIONS/NODE_PATH и лимитом heap 96 MiB. Исходник передаётся через stdin; файлы в контейнере не создаются. Это не запуск workflow или приложения n8n. Ожидаемый максимум выполнения — 30 секунд.

**Main не импортируется и не выполняется.** Компилируется только включённый в одобренный пакет парсер/анализатор. Никаких npm install, SQL, API-платежей, RPC, чтения env, перезапусков, изменения прав или конфигураций. При недоступности Node/контейнера скрипт останавливается; ничего не устанавливает самостоятельно. Сырые ошибки subprocess/parser не выводятся.

## Запуск — только после отдельного согласования

1. Администратор проверяет пакет. После согласования копирует скрипт в `/home/mgdeploy/staging/` под владельцем mgdeploy. Сейчас файла на сервере нет.
2. Проверяет:

```bash
sha256sum /home/mgdeploy/staging/meetguru-club-main-structure-read-20261124.sh
bash -n /home/mgdeploy/staging/meetguru-club-main-structure-read-20261124.sh
```

3. Одобряет указанный SHA через существующий `/etc/mg-deploy/approved.sha`. Агент этот файл не меняет.
4. Запускает:

```bash
sudo /usr/local/sbin/mg-deploy meetguru-club-main-structure-read-20261124.sh
```

5. Передаёт только полученный JSON. Не отправлять сырой main, env, ключ или полные docker logs.

Сам диагностический код не записывает данные. mg-deploy сохраняет свою штатную временную копию скрипта и запись запуска в административном журнале. Откат не нужен: настройки и сервисы не изменяются.
