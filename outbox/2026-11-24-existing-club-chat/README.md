### Точная граница UI

`wwElementComponent.vue` заменяет рендерер только двух существующих шаблонов сообщения:
`05f4fc6d-d561-4c9f-9f57-4af63724f675` (desktop), `2a3ed957-42b8-46a1-8551-58018509e747` (mobile).
Данные берутся из существующего `bindingContext`, без нового запроса или новой подписки SDK на каждое сообщение.
Старые popup просмотра фото и подтверждения удаления вызываются с прежними ID/аргументами.
CSS ограничен UUID существующих контейнеров клуба. `ChatsPage.vue`, `chatAttachments.js`, публичный JSON клуба, SQL, RLS, Storage, подписки/платежи не изменены.

Это точечная правка runtime WeWeb: при повторном экспорте override нужно сохранить. Не является новым чатом или миграцией истории.

### Push: что готово и что НЕ подключено

Обработчик принимает только ID события; клуб/отправитель берутся из БД. Существующие secret-header, VAPID, opt-out `send_notif`, allowlist, fetchSubs, deliver, лимит параллелизма и бюджет отправки сохранены.

- `club_message`: `{ "event": "club_message", "message_id": "UUID" }`.
- `club_post`: `{ "event": "club_post", "post_id": "UUID" }`.
- На экране блокировки только «МитГуру» + «Новое сообщение в клубе» / «Новый пост в клубе».
- Текст, фото, имена, название клуба НЕ читаются для уведомления и НЕ передаются.
- Ссылка открывает существующую `/club/?club=<id>`; автоматическое открытие вкладки чата не заявляется.
- Удалённое сообщение и отложенный пост (`date_send != null`) пропускаются.
- Получатели: владелец + подписчики с `end_date > current_date` (тот же критерий списка `get_club_bundle.subers`), без отправителя и opt-out. `active` не переопределён: это может быть автопродление, а не оплаченный доступ.
- Отсутствующий/посторонний отправитель сообщения не рассылается. Дубликаты получателей убираются.
- До согласования включения ветка fail-closed: `PUSH_CLUB_ENABLED` по умолчанию false. Существующие события продолжают работать независимо от него.

**Это не законченное подключение доставки:** SQL/триггеры и n8n в diff отсутствуют. После отдельного разрешения нужен источник событий в существующем механизме: новый INSERT club_chat и опубликованный club_posts (включая переход date_send в NULL, если так публикует scheduler). Не отправлять повторно на редактирование/лайк. Старый Expo-путь не заменять автоматически. Полная сквозная отправка и дедупликация источника ещё не проверены.
Никакие новые уведомления в production не отправлялись.

### Повторить локально

На чистой копии указанной базы: `git apply --check changes.diff`, затем `git apply changes.diff`.
Использовать существующую установку зависимостей проекта и установленный Playwright (не добавлен в package.json):

```sh
node tests/club-existing.unit.mjs
node supabase/functions/web-push-send/logic.test.mjs
node tests/chat-previews.unit.mjs
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/club-existing.browser.mjs
./node_modules/.bin/vite build -l warn
```

Существующие browser tests содержат устаревший абсолютный путь Playwright. Для проверки использовались временные копии с заменой только этого импорта; продуктовые тесты/зависимости не менялись. Скрипт воспроизведения: `run-existing-browser-tests.mjs`.
