# Отдельное предложение безопасности — НЕ часть функционального diff

Подтверждено read-only 24.11.2026 по метаданным production:

| Объект | Факт |
|---|---|
| public.club_chat | relrowsecurity=false, anon имеет SELECT |
| public.club_posts | relrowsecurity=false, anon имеет SELECT |
| storage.buckets: club | public=true |
| storage.buckets: chat | public=true |

Чужие сообщения, фотографии и клиентские/платёжные персональные данные для подтверждения не выгружались. Метаданные достаточны для фиксации отсутствия серверного барьера. Ссылки и содержимое объектов не публикуются.

Риск: сокрытие вкладки в UI не защищает данные через API; публичная ссылка Storage не требует членства. Новый UI этот существующий риск не исправляет и не позиционируется как исправление доступа.

Минимальное отдельное решение для согласования:

1. Зафиксировать действующий критерий доступа (владелец, оплаченный срок, null end_date, отмена автопродления), не менять бизнес-правила. Существующий список subers и некоторые frontend-условия отличаются в обработке null/границы даты; нельзя молча выбрать новые права.
2. Подготовить адресные RLS/GRANT для club_chat и club_posts: пользователь определяется auth.uid(), чтение только по праву клуба; запись сообщения от собственного UID; публикация/удаление в пределах существующих ролей. Проверить связанные get_club_bundle/модерацию/scheduler, чтобы функция не обходила политику. Не ослаблять другие таблицы и не менять подписки.
3. Отдельно согласовать закрытые вложения: ограничить существующие пути Storage по клубу/владельцу, использовать авторизованную выдачу/временные ссылки. Не переключать общий bucket club в private вслепую: там могут лежать публичные обложки. Нужна инвентаризация только используемых путей и план совместимости старых сообщений.
4. До этого НЕ добавлять новые закрытые файлы/voice и НЕ включать push с текстом/фото/именами/названиями закрытых объектов. В функциональном кандидате payload только общий; включатель по умолчанию false, источник событий отсутствует.
5. При согласовании источника push проверить доверенность записей/получателей и защиту от спама: существующие прямые записи нельзя автоматически считать подтверждением авторства. Запуск доставки не считать завершённым только по unit-тестам.

Никаких SQL, изменений политик, bucket settings, миграций старых вложений или production-операций в этот пакет не включено.
