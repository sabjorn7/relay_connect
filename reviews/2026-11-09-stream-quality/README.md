# MeetGuru: HD / Full HD — локальный кандидат

Production не изменялся. SQL, конфигурация PeerTube, credentials, активные комнаты/эфиры не менялись. Commit/push/deploy не выполнялись. Новые зависимости не устанавливались.

## Реализовано

- Выбор HD (720p) / Full HD (1080p) в создании и редактировании. Отсутствующее значение = HD. Full HD недоступен до серверного включения. Для live показано «при следующем запуске». OBS получает инструкцию, но автоматически не перенастраивается.
- Сохранение `streams.video_quality`; исходные RLS/права/платёжная логика сохранены. Скрытые эфиры не получают новых публичных API/обходов.
- Камера и screen share используют выбранный профиль; VP8, simulcast, adaptiveStream и dynacast сохранены. Основной слой: HD 1,7 Мбит/с, Full HD 4,5 Мбит/с. Запрашивается 30 FPS. Слабая/несовместимая камера не меняет глобальный Egress: constraints имеют fallback, фактическое разрешение показывается с предупреждением.
- Профиль Egress берётся только из БД и проверяется allowlist; `H264_720P_30` / `H264_1080P_30`. Снимок запуска хранится отдельно в `stream_video_runs`, не редактируется клиентом. `/live/token` для работающего эфира возвращает снимок; исторический live без снимка остаётся HD даже при редактировании будущего профиля.
- Резервирование перед созданием Egress; по умолчанию разрешён один одновременный Full HD. Параллельные старты сериализуются в PostgreSQL. Настройка, изменившаяся во время запуска, не фиксируется как другая конфигурация. При неопределённом результате RPC сначала читается состояние; нельзя удалять потенциально успешно запущенный эфир вслепую.
- PeerTube Embed API: ограниченный origin/source-checked jschannel-совместимый клиент; Auto и 1080/720/480 только если их реально объявил плеер. По умолчанию Auto, когда доступен. Ошибка/отсутствие API не удаляет iframe и штатные controls. Список обновляется по событию и каждые 5 секунд. Выбранный профиль плеера не называется измеренным декодированным разрешением.
- Панель ведущего: реальный capture, выбранная камера, слои outbound RTP, измеренный bitrate по двум samples, FPS, packet loss, RTT, jitter, qualityLimitationReason и состояние. Камера опрашивается раз в 3 секунды; WebRTC/серверная статистика — только при открытой панели. Недоступные значения не заменяются нулями. Никаких сетевых диагностических журналов не отправляется.
- Панель Egress доступна владельцу/активному соведущему и существующей роли `users.role='admin'`. Ответ содержит allowlist, не содержит токенов, RTMP-ключей/URL, SDP, ICE/IP или raw ошибок Egress. CPU/RAM и фактический bitrate отсутствуют — показывается «Недоступно».

## Известные ограничения

- Без отдельного изолированного LiveKit/Egress/PeerTube-окружения невозможно подтвердить прохождение реального 1080p. Новый публичный стенд не создавался, пакеты/сервисы не устанавливались.
- Отчёт плеера о выбранном HLS-варианте не равен измерению decoded videoWidth/videoHeight. Буферизация/dropped frames отсутствуют в используемом Embed API и честно недоступны. Для них понадобится отдельно согласованный безопасный postMessage-адаптер на стороне PeerTube; cross-origin iframe не обходится.
- CPU/RAM контейнера и измеренный RTMP bitrate не доступны штатному клиентскому API Egress. Docker socket в orchestrator не передаётся. Для этих показателей нужен существующий мониторинг/отдельный read-only collector, отдельная задача; null не заменяется целевым bitrate.
- Reservation живёт 2 минуты до запроса создания Egress. Перед внешним запросом слот удерживается бессрочно: при таймауте создания или неподтверждённой остановке он не освобождается автоматически. Требуется ручная сверка; это fail-closed предохранитель, не полноценный reconciler внешних сервисов. Перед включением Full HD нужны реальные тесты этих отказов; увеличение лимита без измерений запрещено планом релиза.
- Существующий `isEgressActive` трактует ошибки API как false; текущая stop-функция подавляет ошибки. Эти прежние механизмы не переписывались в рамках профилей. Сбой control plane не является доказательством остановки медиапотока.
- Изменение будущего профиля не перенастраивает уже подключённые камеры. Перед новым запуском после изменения настройки ведущие должны переподключиться; текущий live сохраняется. Для автоматической синхронизации уже подключённых ведущих при будущем старте понадобится отдельный согласованный контракт.
- Сетка делит пиксели всей композиции между участниками; 1080p Egress не означает отдельное 1080p изображение каждой камеры. Слабая камера не меняет выбранный профиль композиции.
